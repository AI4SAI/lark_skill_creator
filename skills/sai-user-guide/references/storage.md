# 存储与数据

**个人 Home** 放自己的环境、脚本和文件。它是个人私有空间；加入组织或接受 Home 扩容资助，都不会使文件变成全组共享。

**组织存储额度池** 是组织的一份总额度，成员工作目录、共享文件夹和课题项目可以共用，也可以为某个目录留出专用份额。例如总共 10 TiB，给一个课题留 2 TiB，其余目录共用 8 TiB；留出的份额即使没用满，也暂时不供其他目录使用。额度分配和文件权限是两回事。

**Home 资助** 让组织为成员的 Home 扩容，环境和数据不用搬家，Home 仍归本人管理。**独立项目** 单独安排存储，不把它的额度当成组织共用池的剩余容量。

判断空间是否不足，要分清包含额度、原生配额和文件系统容量。SAI 的“允许超额”生效后，包含额度与写入硬上限可以不同。控制台的“剩余额度”为负表示用量超过包含额度。超额费用按当前授权和计费规则处理，已有授权内的任务可在实际限制允许时继续。

Lustre 的 `Quota` 是软限额，`Limit` 是硬限额，容量和文件数分别检查。超过软限额时看 `Grace`：`notify` 只提醒，普通宽限期到期后仍超软限额会限制新增分配，硬限额也始终有效。零限额表示该项无限。例：已用 120 GiB、软限额 100 GiB、硬限额 200 GiB、`Grace=notify`，表示超出软限额 20 GiB，距硬限额还有 80 GiB。实际写入还受文件数、其他适用配额和文件系统空间约束。

Agent 收到空间错误时，先保留原始 `EDQUOT` 或 `ENOSPC`，对实际报错路径运行 `sai storage local-quota --format json -- PATH`，同时核对该挂载的容量与 inode。Pilot 的 `storage_native_quota` 查询当前计算工作区，缺少宽限期和超额授权字段，具体路径用上述原生查询补齐。只有软限额超量或用量标有 `*` 时，继续查硬限额与宽限状态，核实后再报告能否写入。临时目录报错也按其真实挂载检查。分额、扩容或更改超额授权沿用现有产品流程。

已授权却打不开文件时，先查站点授权是否生效，再看文件自身权限。程序创建的私有文件、移入或保留原权限复制的文件，可能需要所有者调整。按默认设置新建的文件仍无法共享时，请管理员检查默认协作设置。平台维护协作入口和默认设置，内部文件按原生权限访问。具体见[共享权限 QA](https://vcnn7siwx4yx.feishu.cn/wiki/CYWxwrFPuin9AIk27W7c18ADnSf#doxcnZrUARXBEbpNuadOSd6KxXg)。

硬链接通过不同路径访问同一份数据。撤销一个目录的协作授权后，其他路径已有的访问仍可能保留，建立链接前要检查两边的共享范围和文件权限。

上传、下载或挂载走[数据传输手册](https://vcnn7siwx4yx.feishu.cn/wiki/YUK3w884Vibfzyk3gdZcSTkungh)。计算的临时数据按站点手册使用节点本地缓存，重要结果写回持久存储；不要把缓存、挂载或共享目录当成自动备份。
