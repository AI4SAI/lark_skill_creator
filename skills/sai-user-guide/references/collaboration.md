# 团队协作

先把团队组织起来，再分空间和工作，最后决定让谁参与。日常加人、邀请、授权和调整资源，在[控制台](https://www.open-sai.com/portal/)的组织与项目管理中完成。

| 需要解决的事 | 选择 |
| --- | --- |
| 实验室统一出钱、管理成员和公共资源 | **组织**。成员各用自己的账号，同一个人可以加入多个组织。 |
| 共用赝势、数据和模板，各自跑任务 | **共享文件夹**。它没有自己的计算账户，费用跟着任务所选账户走。 |
| 钱由组里出，但要按课题统计用量 | **课题项目**。共用组织的算力额度和存储池，可为课题设资源上限。 |
| 某个项目需要自己的算力等级、预算和存储 | **独立项目**。可以单独安排订阅或合同等级，组织不用一起升级。钱仍由组织支付，组织也可以设限制。 |

独立项目按自己的服务等级确定算力与队列上限，组织的套餐或合同等级不会自动带给它。预算控制花多少钱，并行算力和队列上限控制用多大，存储额度控制放多少数据。

可以用 GitHub 的思路理解：加入组织，不等于能访问里面所有项目和目录。

| 内容 | 组织成员 | 外部协作者 |
| --- | --- | --- |
| 成员的组织工作目录 | 本人可编辑，其他成员默认可查看 | 必须显式授权 |
| 组织默认共享文件夹 | 默认可共同编辑 | 必须显式授权 |
| 手动创建的项目、共享文件夹 | 必须显式授权 | 必须显式授权 |
| 个人 Home | 只有本人可访问 | 不因组织关系获得访问权 |

平台以共享文件夹、项目目录和成员工作目录的根目录为协作范围。只分享部分结果时，新建共享文件夹放这些结果，再邀请合作者。任意内部子目录不再单独纳入平台权限托管，用户仍可管理自己文件的 Linux 权限。

SAI 维护目录入口、协作者名单和新内容的默认协作设置。内部文件还受所有者和程序设置的权限影响。查看角色授予读取，文件所有权和其他有效授权已有的写权限继续生效。

文件编辑、项目计算分别授权，外部合作者无需加入整个组织。邀请和权限以当前站点的生效状态为准。历史目录首次准备或切换可能处理存量文件，切换完成后日常人员变更不再扫描文件树。

撤权生效后，这项协作授权已收回。旧连接、运行中的程序和已打开的文件仍可能访问，已下载副本仍在对方手中。涉及敏感资料时，请管理员核对需要结束的连接和任务。

存储池和 Home 资助见[存储与数据](storage.md)。共享文件不等于共享 Pilot 对话，对话协作见[Pilot](pilot.md)。

加入组织后的访问范围、Home 隐私、部分数据共享、查看角色和撤权，见[团队协作 FAQ](https://vcnn7siwx4yx.feishu.cn/wiki/DxGewwDXgighARk7OWHcAzLqn6f#doxcnEJnmwuKAHFeXzpt8USfTPg)。
