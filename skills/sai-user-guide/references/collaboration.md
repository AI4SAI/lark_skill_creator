# 团队协作

先把团队组织起来，再分空间和工作，最后决定让谁参与。日常加人、邀请、授权和调整资源，在[控制台](https://www.open-sai.com/portal/)的组织与项目管理中完成。

| 需要解决的事 | 选择 |
| --- | --- |
| 实验室统一出钱、管理成员和公共资源 | **组织**。成员各用自己的账号，同一个人可以加入多个组织。 |
| 共用赝势、数据和模板，各自跑任务 | **共享文件夹**。它没有自己的计算账户，费用跟着任务所选账户走。 |
| 钱由组里出，但要按课题统计用量 | **课题项目**。共用组织的算力额度和存储池，可为课题设资源上限。 |
| 某个项目需要自己的算力等级、预算和存储 | **独立项目**。可以单独安排订阅或合同等级，组织不用一起升级。钱仍由组织支付，组织也可以设限制。 |

独立项目按自己的服务等级确定算力与队列上限，组织的套餐或合同等级不会自动带给它。预算控制花多少钱，并行算力和队列上限控制用多大，存储额度控制放多少数据。

可以用 GitHub 的思路理解：加入组织，不等于能访问里面所有项目和目录。

| 内容 | 组织成员 | 外部协作者 |
| --- | --- | --- |
| 成员的组织工作目录、组织默认共享文件夹 | 默认可访问 | 必须显式授权 |
| 手动创建的项目、共享文件夹 | 必须显式授权 | 必须显式授权 |
| 个人 Home | 只有本人可访问 | 不因组织关系获得访问权 |

外校合作者只需要看结果，就授权结果目录；需要一起修改，给编辑权限；需要用项目资源跑任务，再给计算权限。无需为了分享一个目录让对方加入整个组织。邀请是否已接受、站点权限是否已生效，要分别看实际状态；合作结束后收回相应授权。

存储池和 Home 资助见[存储与数据](storage.md)。共享文件不等于共享 Pilot 对话，对话协作见[Pilot](pilot.md)。
